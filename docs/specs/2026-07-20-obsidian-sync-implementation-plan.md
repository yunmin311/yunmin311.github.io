## 一、工具体检结果:obsidian-export 过关,但有一个必须的附加条件

2026-07-20 在本机实测(版本 25.3.0,官方 Windows 包,sha256 已核对)。
搭了一个迷你 vault:发布文件夹里两篇互链的笔记 + 一张附件图,发布文件夹**外**
一篇私密日记和一张图,正文里布下六种情形。结果:

| 情形 | 结果 |
|------|------|
| 链到发布文件夹内的笔记 | ✅ 翻成标准 markdown 链接 |
| 链到根本不存在的笔记 | ✅ 降级成纯文字(斜体),出警告 |
| 链到库里存在、但发布文件夹外的私密笔记 | ⚠️ **分两种**,见下 |
| 带别名的双链降级后 | ✅ 显示的是**别名**,原标题完全不出现(意外之喜) |
| 发布文件夹内的附件 | ✅ 原样复制,子目录结构保留 |
| 发布文件夹外的附件被嵌入 | ✅ 不复制,正文里的嵌入被删掉(不泄露) |
| frontmatter | ✅ 原样保留 |

那个 ⚠️ 是这次体检最重要的发现:

- **只用 `--start-at`(按子文件夹导出)**:链到发布文件夹外的笔记**不降级**,
  反而生成一条带库内相对路径的完整链接——私密笔记的标题和路径全暴露,**踩红线**;
- **在 vault 根加一个 `.export-ignore` 文件**(内容就两行:`/*` 和 `!/发布文件夹名`,
  意思是"除了发布文件夹,全部当不存在"):同样的链接**正确降级成纯文字**,
  路径和链接都不出现。

**结论:选定 obsidian-export,备胎(@flowershow 插件 / 纯自写)不用上。
附加条件写死:vault 根必须有那个两行的 `.export-ignore`——它才是隐私的墙,
`--start-at` 只管"导哪个文件夹",不管"链接怎么降级"。
管线开跑前自动检查这个文件在不在、内容对不对,不对当场停**(红线机器化,不靠记性)。

另外两个实测事实,直接影响下面的设计:

- 工具就算出警告,**退出码也是 0**(不报失败)——把关不能指望它,
  靠我们自己的检查步骤(验票、扫 `[[` 残留);
- 工具对图片只做**原样复制**,不动内容——抹 EXIF/GPS 靠我们的图片关卡
  (本来就是这么设计的,分工正好)。

## 三、按一下按钮之后(管线细节,落实 spec 第三节五步)

私有笔记库的动作,手动触发,按顺序:

1. 官方 `actions/checkout` 检出笔记库自己;
2. 下载 obsidian-export **固定版本 25.3.0** 并核对 sha256(供应链把关,料变了就停);
3. **守门**:检查 `.export-ignore` 在且内容正确,不对当场停;
4. 导出:`--start-at 发布文件夹` → 临时目录;
5. 官方 `actions/checkout` 用 secrets 里的钥匙检出公开仓库(凭据只经官方步骤,全程不打印);
6. 在公开仓库检出里装依赖(sharp 已在),跑 `node scripts/sync/run.mjs`;
7. 胶水脚本四道关,任何一道不过就整个失败、什么都不推:
   - **验票**:基线三件套(标题+日期+简介)+ 各板块 spec 标了必填的字段
     (项目记录:项目名+类型标记;学习记录:学习线;代码库:仓库链接+类型标记),缺一拦下;
   - **扫残留**:导出产物里还有 `[[` 就拦(不该发生,发生了就是出事了);
   - **图片关卡(红线)**:附件逐张过 `scripts/prep-image.mjs`(压缩+抹 EXIF/GPS),
     HEIC 或处理失败当场停;转成 JPG 后,正文里的图片引用同步改名改路径;
   - **落位**:md 按板块进对应集合目录,图进约定的图片目录,路径全部改成网站惯例;
8. 显式路径 `git add` 三个内容目录,提交、推送公开仓库。

要点两条:

- **全量镜像**:发布文件夹是唯一事实源——在 Obsidian 里删掉/移走的笔记,
  下一次同步在网站仓库同样删掉("移出去 = 撤下",spec 第二节的承诺靠这个兑现);
- **同步 ≠ 上线**:推进公开仓库 = 全网可见(仓库本身公开),但网站部署照旧另一道手动闸。

## 四、两个记录在案的取舍(不拦本轮,单独可议)

1. **图片统一转 JPG**(prep-image.mjs 现行规则):截图的文字边缘会有一点点糊;
   好处是体积小、抹元数据这条路已验证。想要截图更清楚,将来给脚本加 PNG 通道——
   但那是改红线脚本,单独提出来议,不夹带;
2. **笔记互链先原样落库**:链到同板块另一篇发布笔记的,现在会翻成 `xxx.md`
   相对链接进仓库。板块页面还没建、网址规则还没定,没有页面会渲染它,先不动;
   等第一个板块建页面时再定"互链翻成站内网址"的改写规则。记录为开口。

4. **试跑**:用户按按钮,我逐条红线核对公开仓库收到的东西(spec 第八节第 3 步),

5. **批量使用**。上线前检查清单里"同步管线抽查三样"那条从此生效。

## 六、红线对照(spec 第六节逐条落点)

| spec 红线 | 落在哪 |
|-----------|--------|
| 附件必过 prep-image.mjs,无旁路 | 胶水第三关,自动;工具只会原样复制,唯一进仓库的路是关卡输出 |
| 只发布专门文件夹,永不同步整库 | `--start-at` + `.export-ignore` 双保险 + 开跑前守门检查 |
| vault 独立干净只装笔记 | 操作单里核对一句(现状已是独立私有笔记库) |
| 凭据只经官方步骤、不打印 | 唯一用钥匙处是官方 checkout;工具二进制有 sha256 校验;第三方 action 一个不用 |

## 七、本轮明确不做

- 不建钥匙、不碰私有笔记库(第 2、3 步只交付文本和步骤,动手的是用户);
- 不建板块页面、不动视觉、不加导航;
- 不做"同步完自动部署"(两道闸照旧);
- 不解决笔记互链的站内网址改写(第四节第 2 条,开口留给板块开工时)。
