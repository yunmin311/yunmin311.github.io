# 首次加载顺序优化 · 2026-10-05

分支 `codex/startup-load-order`，基于已发布 `51c8038`。用户反馈桌面全部组件约六秒就绪，手机正常且更快。本轮只做本地优化与对照，不自动提交、推送或部署。

## 复现

同一 Chromium、1440/390、空缓存、10Mbps、40ms 网络延迟、CPU 四倍减速，每组重复三次。静态预览服务器不提供 gzip；不能把结果等同 GitHub Pages 或用户实际设备秒数。完整就绪定义：控件、3D、印刷贴图、首云及三层云数据都 ready；首层就绪和未来云层预取分别记录，不以删除内容换速度。

原版控件约3.1秒、桌面印刷贴图约6.4秒、三层云约7.2秒；手机模拟三层云约7.5秒。资源瀑布证实：manifest→缓存与model JSON→scene/runtime→print→首云→后续云与定稿贴图。原模型先请求旧 diffuse 贴图229239字节，再加载定稿贴图689372字节（均不含HTTP头）。

## 保留的优化

- HTML 提前发现 runtime、scene、print 三份脚本，仍使用原文件和缓存，不替换功能。
- 配置准备后同时启动 print、scene、runtime，印刷材质不再等控件初始化结束。
- 云初始化 Promise 不再阻塞照片/印刷贴图的后续准备。
- 桌面（宽度≥900且精确指针）模型解析前使用同一张定稿印刷贴图；已加载该图时直接复用，不再通过 TextureLoader 再下载/解码/上传一份。几何、相机、灯光、阴影、材质参数不改。原图与PNG/WebP回退保留，未重新生成素材。手机继续用原来的小首图先显示3D，再载入定稿材质，避免首个模型延后。

桌面提前低优先下载第二/第三云的试验撤回：尽管全部数据略早完毕，首层云由约4.8秒拖到约6.3秒。最终 cloud-flow/cloud-canvas 与已发布版逐字一致；手机当前云优先和滚动采样完全保留。

## 边界

不做手机触摸扰动；不减少手机内容。不声称消除所有网络或硬件差异；未实测实体手机、Safari/Firefox/Edge、本轮线上加载速度。
