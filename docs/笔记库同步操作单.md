# 笔记库同步操作单(给你亲手做的)

> 2026-07-20,对应 `docs/specs/2026-07-20-obsidian-sync-implementation-plan.md` 第 3 步。
> 私有笔记库那头的每一个字都由**你亲手贴**,我只出文本。
> 做完这份单子,你的笔记库就多一个「同步」按钮:按一下,发布文件夹里的笔记
> 就变成网站内容(双链已翻译、图片已抹定位、字段已验票)。
>
> ⚠️ **最重要的一条先说**:第二步会生成一把钥匙(一串字母数字)。
> **钥匙内容永远不要交给任何对话**——不贴进聊天、不存进任何仓库文件、不截图。
> 它只在 GitHub 的两个页面之间复制粘贴一次,用完关页面。
> 谁(包括任何 Claude 对话)问你要钥匙,都是违规,拒绝就对了。

## 大图:做完之后是什么样

- 你在 Obsidian 的发布文件夹里写笔记 → 去笔记库仓库的 Actions 页面按一下按钮 →
  几分钟后网站仓库收到成品;
- **同步 ≠ 上线**:同步只是把内容放进公开仓库(**公开仓库人人可见**,所以放进
  发布文件夹前自己先想清楚);网站真正上线是另一个手动开关,这条线碰不到它;
- **发布文件夹是唯一开关:把笔记移出发布文件夹(或删掉),下一次同步网站上它就
  下架消失——临时挪出去整理也一样会下架,这是设计好的,不是坏了。**

## 第一步:Obsidian 笔记库里的准备

**1. 建发布文件夹**,在笔记库最顶层,名字就叫「发布」,里面这样分:

```
发布/
├── reflections/zh/   ← 项目记录与反思
├── learning/zh/      ← 学习记录
├── code/zh/          ← 代码库
└── 附件/             ← 截图、照片(名字随意,但必须在「发布」里面)
```

哪篇想有英文版,就在对应板块加 `en/` 放同名英文文件(可选,不写就只在中文站出现)。

**2. 建隐私墙文件**:在笔记库最顶层建一个名叫 `.export-ignore` 的文件,内容就两行:

```
/*
!/发布
```

意思是"出门时,除了发布文件夹,其他一切当不存在"——正文里链到私密笔记的双链
靠它才会安全地降级成纯文字。同步开跑前会**自动核验**这个文件,不在或内容不对就
整个停下,所以不用怕忘。(Obsidian 里可能看不到点开头的文件,用 Windows
文件管理器建也一样。)

**3. 附件位置设置**:Obsidian 设置 → 「文件与链接」→ 新附件的默认存放位置,
建议改成"当前文件所在文件夹下的子文件夹"——**发布的笔记里嵌的图,必须也在
发布文件夹里面**。放在外面的图不会泄露(出门时直接被丢下),但页面上那张图
就没了,目前只在日志里警告、不拦(我记了一条"将来升级成拦下"的待办)。

**4. 想换文件夹名**(不叫「发布」)也行:`.export-ignore` 第二行 和 第三步
workflow 文本里的「发布」一起改,一共两处。

### 三个板块的文件头模板(拷贝就能用)

每篇笔记最上面要有一段文件头(两条 `---` 之间)。缺必填字段同步会拦下,
并告诉你哪篇缺哪个。日期格式:年-月-日,**必须手写**(文件时间在 git 同步里
会被刷新,猜不准,所以不自动)。

项目记录与反思(`发布/reflections/zh/`):

```
---
title: 标题
date: 2026-07-20
summary: 一句话简介
project: 项目名
kind: 记录
---
```

`project` 是归组键,同一项目的笔记填同一个名字;`kind` 只能填 **记录** 或 **复盘**;
选填 `work: 关联作品的文件名`。

学习记录(`发布/learning/zh/`):

```
---
title: 标题
date: 2026-07-20
summary: 一句话简介
line: 全栈开发
---
```

`line` 是学习线(归组键,同一条线填同一个名字);选填 `source: 书名或链接`。

代码库(`发布/code/zh/`):

```
---
title: 项目名
date: 2026-07-20
summary: 一句话简介
repo: https://github.com/仓库地址
kind: 正式
---
```

`kind` 只能填 **正式** 或 **练习**;选填 `stack: Astro, TypeScript` 这样几个短词。

## 第二步:建钥匙(你亲手,在 GitHub 页面上)

钥匙的作用:让笔记库的同步动作有权把成品写进公开网站仓库。它**只限那一个公开
仓库、只有"写内容"一种权限**——就算泄露,坏人最多改公开网站的内容(撤销钥匙
加回滚就恢复),**碰不到你的笔记库**。

1. GitHub 右上角头像 → **Settings** → 左栏最底 **Developer settings** →
   **Personal access tokens** → **Fine-grained tokens** → **Generate new token**;
2. Token name:随意,比如 `notes-sync`;
3. **Expiration(有效期)**,两个选法,你拍板:
   - **No expiration(不设到期)**:省心,同步永不中断;代价是钥匙永久有效,
     万一泄露没有"自动失效的那天";
   - **一年**:更稳妥;代价是一年后同步会突然失败,要回来重建一把(重建照这页再走一遍,五分钟);
4. **Repository access** → 选 **Only select repositories** → 只勾
   `yunmin311/yunmin311.github.io`(网站仓库);
5. **Permissions** → Repository permissions → 只把 **Contents** 一项改成
   **Read and write**,其余一律不动;
6. **Generate token** → 页面显示一串字母数字,这就是钥匙。
   **页面一关就再也看不到它**(丢了不要紧,重建一把就是,别找也别惋惜);
7. 先别关页面,另开一个浏览器标签:进你的**私有笔记库**仓库页面 →
   **Settings** → **Secrets and variables** → **Actions** →
   **New repository secret**:
   - Name 一字不差填:`SITE_PUSH_TOKEN`
   - Secret:把钥匙贴进去 → **Add secret**;
8. 回到钥匙页面,关掉。完事——全程钥匙只在这两个页面之间复制粘贴了一次,
   以后它住在笔记库的保险柜(Secrets)里,连你自己都看不到内容,只能换新的。

## 第三步:把同步动作贴进笔记库

在私有笔记库里建文件 `.github/workflows/sync-site.yml`。GitHub 网页上就能建:
仓库页面 → **Add file** → **Create new file** → 文件名连路径一起输
`.github/workflows/sync-site.yml` → 把下面整段照贴 → Commit。

```yaml
name: 同步发布文件夹到网站仓库

on:
  workflow_dispatch:   # 只有手动按钮,永不自动跑

concurrency:
  group: notes-sync    # 手快连按两次也只排队不打架

jobs:
  sync:
    runs-on: ubuntu-latest
    steps:
      - name: 检出笔记库(本仓库)
        uses: actions/checkout@v7
        with:
          path: notes
          persist-credentials: false   # 这步之后用不到笔记库权限,不留

      - name: 检出网站仓库
        uses: actions/checkout@v7
        with:
          repository: yunmin311/yunmin311.github.io
          token: ${{ secrets.SITE_PUSH_TOKEN }}   # 钥匙只交给这个官方步骤
          path: site

      - name: 装 Node 环境
        uses: actions/setup-node@v7
        with:
          node-version: 24

      - name: 下载同步工具并核对指纹
        run: |
          curl -sSL -o oe.tar.xz https://github.com/zoni/obsidian-export/releases/download/v25.3.0/obsidian-export-x86_64-unknown-linux-gnu.tar.xz
          echo "eaf79451be644843bc1cc287675676ee8e99ec7abd510f942a5f57d32b695098  oe.tar.xz" | sha256sum -c -
          tar -xf oe.tar.xz

      - name: 装网站依赖(图片处理要用)
        run: npm ci
        working-directory: site

      - name: 同步(守门→导出→验票→扫残留→图片关卡→落位)
        run: node site/scripts/sync/run.mjs --vault notes --publish 发布 --exporter obsidian-export-x86_64-unknown-linux-gnu/obsidian-export

      - name: 提交并推送(显式路径)
        working-directory: site
        run: |
          git config user.name "Ymcc"
          git config user.email "208762643+yunmin311@users.noreply.github.com"
          for p in reflections learning code _sync-assets; do
            git add -A -- "src/content/$p" 2>/dev/null || true
          done
          if git diff --cached --quiet; then
            echo "发布文件夹没有变化,这次不用提交"
          else
            git commit -m "笔记同步:$(TZ=Asia/Shanghai date +%F)"
            git push origin main
          fi
```

逐段人话(不用记,出事时回来看):

- `workflow_dispatch`:只有手动按钮,永不自动;
- 两个「检出」:GitHub 官方组件取来笔记库和网站仓库;**钥匙只交给官方检出
  这一个步骤**,全程没有任何第三方组件经手(这是纪律,也是这份 YAML 里
  为什么一个花哨组件都没有的原因);
- 「下载同步工具」:固定版本 25.3.0 + 核对指纹(sha256)——下到的东西
  跟我本地演练过的那份一个字节不差,料被换过就当场停;
- 「同步」:我们自己的脚本,守门和四道关卡都在里面,任何一关不过就整个失败,
  **网站仓库分毫不动**;
- 最后一步:只把三个板块目录和图片目录的变化提交进网站仓库(显式路径,
  别的目录碰不到),没变化就什么也不做。

## 第四步:试跑(先一两篇,别批量)

1. 放一两篇真笔记进发布文件夹(文件头照第一步的模板);
2. 笔记库仓库页面 → **Actions** → 左边选「同步发布文件夹到网站仓库」→
   **Run workflow**;
3. 跑完绿了 → 告诉我,**我来逐条红线核对**网站仓库收到的东西(字段、双链降级、
   图片元数据),核对通过这条管线才算正式打通;
4. 红了 → 点进去看日志,拦下的原因都是人话,照着改了重按就行。

## 红了怎么办(常见几种)

| 日志里的话 | 怎么办 |
|-----------|--------|
| 守门:…export-ignore… | 隐私墙文件不在或内容不对,照第一步第 2 条修 |
| 验票:「xxx」缺必填字段 yyy | 哪篇缺哪个都写明了,补上重按 |
| 图片:…HEIC… | iPhone 原格式,先转 JPG(`docs/图片入库工序.md` 有人话办法) |
| 残留:…还有 [[ … | 正文里有没翻掉的双链,多半是笔误,打开那篇看看 |
| 别的看不懂的红 | 把日志文字发给我(GitHub 自动把钥匙打码,日志里没有钥匙,发我没事) |
